# 담당 학생 명단과 학생별 관리 · v10

교사 로그인은 담당 학생 명단에서 시작합니다. 이름이나 ‘학생 관리 열기’를 선택하면 기존 학습·복습 기록, 10개 작문 검토, 교사 평가·부모 자료 메뉴를 사용합니다. 관리 중인 학생 이름과 반을 계속 표시하며 명단으로 돌아가 다른 학생을 선택할 수 있습니다. 교사 새로고침은 명단에서 시작하고, 학생을 다시 선택하면 저장된 관리 페이지를 엽니다.

명단은 이름·아이디·반 검색과 반 필터를 제공합니다. 정규 객관/작문 제출 진행과 최신 작문 버전의 검토 대기 수는 각 학생의 실제 데모 기록으로 계산합니다. 학습을 하지 않은 학생의 성적·제출 기록을 만들어 넣지 않습니다.

| 가상 인물 | 역할 | 테스트 아이디 | 비밀번호 |
| --- | --- | --- | --- |

| 김선생 | 세 학생을 담당하는 교사 | `test2` | `test2` |

마스터 로그인은 현재 없습니다. 향후 학원 관리자 역할을 추가한다면 교사·학생 계정, 반, 담당 교사 배정과 권한을 관리하는 별도 역할로 설계합니다. 이번 요청에서는 그 역할을 임의로 추가하지 않았습니다.

## 기록과 기존 데이터

각 학습 기록에 `studentId`를 두고 학생마다 독립된 브라우저 저장 키를 사용합니다. 이지우는 기존 `vocabulary-pilot-flow-v2`를 유지하고, 새 학생은 `vocabulary-pilot-flow-v2:student-doyoon`과 `vocabulary-pilot-flow-v2:student-seoyeon`에 저장합니다. 이름 없는 기존 v2 기록과 v1 이력은 이지우에만 이어받습니다. 기존 학습 문항·교재 어휘 순서·배정·판정 규칙은 그대로입니다.

답안·초고·수정본·작문 판정·교사 코멘트·부모 자료·복구 기록을 분리합니다. 저장 실패 때 현재 창의 입력을 학생 전환 후에도 유지합니다. 이전 학생의 남은 이벤트나 늦은 호스트 저장 응답이 다음 학생에게 적용되지 않도록 하고, 다른 학생의 호스트 상태를 거부합니다. JSON·부모 출력·초기화는 선택한 학생만 대상으로 하며 명단에서 실행되지 않습니다. 학생을 바꾸거나 명단으로 돌아갈 때 기존 인쇄·JSON 패널도 지웁니다.

## 실제 검증

- [VM 검증](vm-results.json): 학생별 기록, 기존 데이터 이전, 교사 판정·부모 메시지 분리, 선택 학생 초기화, 오래된 화면 이벤트, 저장 실패·손상·소유 학생 불일치, 다른 학생의 호스트 상태와 늦은 저장 응답 등 **19개 통과**.
- [실제 Chromium 검증](browser-results.json): 같은 브라우저의 두 학생 탭에서 각각 객관 10개·작문 10개 제출, 교사 명단→선택→검토·리포트, 학생별 JSON·인쇄/PDF, 검색·반 필터·키보드 선택, 두 디자인의 320/360/390/768/1280px 화면, 새로고침·선택 학생 초기화 등 **8개 통과**.
- [현재 통합 검증](../validation-summary.json): 현재 HTML 해시에서 VM 115개, 콘텐츠 구조 22개, 실제 로컬 Chromium 47개로 **184개 통과, 실패 0개**. 이전 v9의 core VM/비교/패키지 기록은 현재 합계에 포함하지 않았습니다.
- [현재 로컬 패키지 검증](build-results.json): 공개 HTML·매니페스트·일러스트 열한 장을 확인합니다.
