# 테스트 배포 전 추가 수정: 손상된 보기 순서 복구

- 중요도: P2. 저장값이 손상된 경우의 복원 결함 1건이며, 정상 화면의 보기 섞기는 중복을 만들지 않습니다.
- 재현: 현재 문항의 `choiceOrders[문항 ID]`를 같은 오답 ID 4개로 저장한 뒤 다시 엽니다. 수정 전에는 4개 버튼 모두 같은 오답이며 정답 버튼이 사라집니다. 당시 구조 검사는 정상으로 판정하고 원문을 복구 기록으로 보관하지 않았습니다.
- 수정: 저장된 순서가 해당 문항 보기 ID 전체의 중복 없는 순열인지 검사합니다. 잘못된 순서는 원문을 격리하고 해당 순서만 다시 섞습니다. 정상 순서, 학생의 첫 답·재시도·미제출 선택·작문 초안·화면 이동 기록을 유지합니다. 이미 배정된 과거 문항과 기간 복습의 스냅샷 보기 ID를 우선합니다.
- 검증: Node VM와 모의 DOM·저장소로 16개 확인 항목 통과. 같은 검사를 수정 전 v5 HTML에 실행했을 때 12개 조건이 실패했으며 모두 이 결함의 복구·격리·보존 조건에 해당합니다. 서로 다른 12개 결함으로 집계하지 않습니다.
- 정상 흐름 확인: 진단 → 객관 10개 → 작문 10개 → 주간·월간·분기 각 10개 복습 → 교사 10개 판정 → 부모 문구 확정 → 인쇄 자료 준비 → JSON 내보내기 → 저장값 재로드를 모의 실행했습니다.
- 한계: 실제 브라우저의 렌더링·저장·끌어 놓기·모바일·인쇄를 검증한 결과는 아닙니다. 기존 브라우저 기동 제한을 다시 시도하지 않았습니다. 서버 저장·인증·기간 집계는 시제품에 없는 별도 개발 범위입니다.

결과는 `choice-order-regression-results.json`, 수정 전 비교는 `choice-order-before-results.json`에 있습니다. 수정 전 비교 대상은 기존 v5 ZIP의 HTML을 임시 경로에 추출한 파일이며 SHA-256은 `0a673ee9af68b60cbab439a8772794ffdedf4615200fd31faaf49b6dbbff3d53`입니다. 수정 후 결과의 SHA-256은 실행 시점 소스를 가리킵니다.
