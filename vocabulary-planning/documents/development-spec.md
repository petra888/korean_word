# 어휘 학습 프로그램 개발용 상세 명세와 검수 계획

작성일: 2026년 10월 4일 · 기준: PRD F01–F26 및 최신 학습 흐름·교사 3버튼 판정·확정 도넛 요구 · 상태: QA 개선 v5를 반영한 개발 착수 명세

이 문서는 개발팀이 화면, 데이터, API, 콘텐츠 관리와 검수 작업을 나누기 위한 자료다. 현재 서비스가 구현되었거나 검수를 통과했다는 뜻은 아니다. 학원, 학생 수, 사용 기기, 예산, 운영 시간과 납품일은 확정되지 않았다. 가상 학생과 로컬 시제품은 실제 학생 기록을 저장·평가하는 납품 서비스와 구별한다.

## 1 범위와 운영 가정

첫 납품 범위는 학생·교사 별도 진입과 서버 권한, 10개 사전적 의미와 무작위 단어 매칭 진단, 60·30·10 객관 집중학습, 혼합 문맥 추론, 10단어 전수 작문·교사 이해 판정·수정, 간격 복습, 주간·월간·분기 전수 복습, 일간·주간·월간 분석, 교사 직접 평가·부모 메시지, 한 학생의 학부모 PDF, 교사용 CSV, 별도 익명 홍보 요약, 승인 콘텐츠 운영이다.

운영 설계의 출발 가정은 학원 1곳, 초등 고학년 약 30명, PC·태블릿 웹서비스, 10개 어휘 묶음, 주 3회 정규 학습이다. 이는 사용자가 선택한 값이 아니다. 기본 디자인 B에 C의 문맥 단서와 D의 작문 수정 흐름을 결합하는 안도 팀의 권장안이다. 학생층·기기·디자인 결정에 따라 변경한다.

다음 항목은 후속 범위다: 자동 발송, 학부모 로그인, AI 의미 판정·자동 요약, 음성 입력, 결제, 외부 학원 시스템 연동, 네이티브 앱, 공개 순위. 기존 첫 납품 기능을 후속 범위로 축소하지 않는다.

실제 학생에게 공개하기 전에는 교재 디지털 이용·변형 권한, 국어 담당자의 콘텐츠 승인, 실제 교사 운영량, 계정·기록 보관·지원 책임과 계약 조건이 확인되어야 한다. 예산·일정·인력은 작업분해와 산정 입력을 근거로 정한다.

새 작문 제출일에 교사 평가가 끝났다고 표시하지 않는다. 학생은 10개 단어의 초고를 모두 제출한 뒤 교사 검토를 기다리지 않고 복습으로 이동한다. 전수 작문을 여러 날로 나누는 운영 가정에서도 같은 묶음의 10개 완료 여부를 보존하며 이미 제출한 문장을 다시 쓰게 하지 않는다. 검토 완료된 이전 작문은 다음 접속에서 수정한다. ④의 전체 복습은 정규 활동과 별도 배정·집계한다. 사전·사후·7일 이상 지연 측정은 측정용 단계로 따로 기록한다.

## 3 역할과 접근 권한

| 역할 | 조회 | 변경 | 출력·운영 |
| --- | --- | --- | --- |
| 학생 | 자신의 승인 과제·답안·피드백·복습·기록 | 자신의 매칭 배치·모른다 응답, 객관 답안, 10개 초고·수정본 | 자신의 결과 화면만 |
| 교사 | 소속 학원에서 담당하는 반·학생의 기록 | 담당 과제, 보조 수준, 배정용 상태, 작문 평가, 리포트 의견 | 담당 범위 CSV·개인 PDF·별도 익명 요약 |
| 학원 관리자 | 소속 학원의 반·계정·운영 상태 | 교사 배치, 반 등록, 계정 복구·종료, 학원명·로고 | 계약상 허용한 소속 학원 운영 자료. 학생 답안 열람은 별도 명시된 권한 |
| 서비스 콘텐츠 승인자 | 원문·어휘·활동 버전·검수 기록 | 콘텐츠 검수·승인·보류·교정 공개 | 교육 콘텐츠 운영. 역할 자체로 학생 답안이나 타 학원 개인정보를 열람하지 못함 |

학생·교사 로그인과 메뉴는 분리한다. 데모의 역할 탭은 화면 비교 기능이며 인증 수단이 아니다. 실제 권한은 인증된 계정의 학원 소속, 담당 반, 학생 ID와 수행할 동작을 서버에서 검사한다. 클라이언트가 보낸 `academy_id`, `student_id`, `role`을 신뢰하지 않는다. 교사 계정도 다른 학원의 동일 URL·ID에 접근할 수 없다.

학생 계정의 간편 접근 방식은 반 코드+개인 PIN을 가정한다. PIN은 평문 저장하지 않고 로그인 재시도 제한, 세션 만료와 교사의 복구 흐름을 제공한다. 공용 기기의 학생 전환 시 세션과 개인 화면 캐시를 종료한다. 이전 학생의 브라우저 뒤로 가기·새로고침·직접 주소 접근도 권한 검사 대상이다. 제출 대기 중이면 저장 상태와 종료 영향을 알려 주고 다른 학생 세션에 미전송 답안을 섞지 않는다.

학생의 반 이동 시 활동 당시 반·교사와 현재 접근 권한을 분리한다. 이동으로 과거 집계 소속을 변경하지 않는다. 기록 인계 범위는 학원 운영 정책으로 결정하며 변경 기록을 남긴다. 학생 삭제·계약 종료 시 내보내기·보관·삭제 절차와 보존 기간은 도입 계약에서 확정한다.

## 4 콘텐츠 등록 승인 교정

### 4 1 원문과 교육용 의미 단위

원문 450행은 출처 기록이며 승인 의미 ID 450개를 뜻하지 않는다. 원문 표제어 문자열은 444개이고 438개 어휘 가족은 잠정 교정 후보다. 원문 번호는 누락·건너뜀이 있으므로 내부 키로 쓰지 않는다. 원문 `source_order` 1–450을 중복 학습행까지 포함해 교재 순서로 보존한다. 1–10, 11–20부터 441–450까지 10행씩 총 45묶음을 구성하고 순서와 위치를 임의로 바꾸거나 건너뛰지 않는다. `source_row_id`에 PDF 페이지·행·원문 번호·표제어·뜻·예문을 보존하고 별도 `meaning_id`로 승인된 교육용 의미를 관리한다. 같은 활용형은 의미 검수 뒤 묶을 수 있지만 서로 다른 뜻은 자동 합치지 않는다.

첫 묶음은 PDF 1쪽 W0001–W0010의 까탈·깜냥·달포·말미·선잠·강단있는·격의·융통성·굴지·기탄없이 순이다. 이전 임의 선별 10단어 묶음은 폐기한다. W0004·W0006·W0008·W0010은 원문 검수 보류 사유가 있어도 삭제·대체·건너뛰지 않고 해당 위치를 유지한 채 승인 보류로 남긴다. 중복 어휘도 원문 ID·위치를 먼저 보존하고 같은 의미 연결·복습 중복 제거는 교육 담당자의 의미 ID 승인 뒤에 적용한다. 진단 왼쪽과 전수 작문 순서는 교재 순서이며 오른쪽 단어와 객관 문항·선택지의 표시 순서만 무작위로 섞는다.

시범 10개 학습 묶음은 신규 제작 초안이다. **현재 실서비스 공개 상태는 10개 모두 보류**이며 실제 국어 담당자의 승인과 권리 확인 전 `approved/published`로 바꾸지 않는다. 문서를 검토하거나 데모에서 문항을 보는 행위는 교육 승인에 해당하지 않는다.

### 4 2 상태와 입력 필드

상태 흐름은 `draft → in_review → approved → published`다. 오류·권리 미확인·복수 정답은 `held`로 보류하고 사유를 기록한다. 공개 후 수정은 새 버전을 만들고 같은 검수 흐름을 거친다. 이전 버전은 `retired`로 신규 배정을 중단하되 이미 배정된 답안 재현용으로 보존한다.

| CSV 종류 | 필수 입력 | 검수·업로드 동작 |
| --- | --- | --- |
| 원문 행 | source_row_id, source_order, printed_number, source_file, page, row_position, raw_headword, raw_definition, raw_example | 기존 원문을 덮어쓰지 않으며 450행·source_order연속·원문중복행·중복키·출처 확인 |
| 교육용 의미 | meaning_id, source_row_ids, display_headword, part_of_speech, approved_sense, easy_definition, accepted_forms, confusion_group, support_level, rights_status, review_status | 원문 연결, 뜻·활용형·연령 읽기 부담 검수 |
| 활동 버전 | activity_template_id, version, meaning_id, primary_target_id, type, level, prompt, options, accepted_answers, clue_keys, explanation, writing_judgment_labels, teacher_guidance, judgment_rule_version, stage_eligibility, assessment_form_id | 실제 중심 단어, 단일 정답, 정답 노출·학습/측정 재사용 여부 검수 |

관리 화면에서 CSV 업로드 → 형식·중복·참조 오류 미리보기 → 검수 요청 → 교육 검토 → 승인 공개를 수행한다. 가져오기 배치는 `import_batch_id`로 추적하고 일부 오류 행을 임의 공개하지 않는다. 검수자, 검수 시각, 승인·보류 사유와 권리 확인 정보를 보존한다. 교사는 승인 문항을 배정할 수 있지만 미승인 초안을 학생에게 직접 공개할 수 없다.

진단 API는 사전적 의미 10개와 무작위 단어 10개를 문항 자극으로 보내지만 정답 매핑·해설·검수 메모를 미리 보내지 않는다. 진단 뜻은 `definition_diagnostic.definition_for_check`에 저장하고 표제어 자체가 풀이에 노출되지 않는지 사전과 대조한다. 현재 뜻풀이는 사전 대조·교육 승인 전 초안이다. 모른다 선택 때만 해당 행 정답을 즉시 자동 배치하며 공개 직전 전체 배치와 노출 시점을 먼저 서버에 기록한다. 이해·추론 API는 첫 제출 전에 중심 목표어 이름·정의·정답 키·해설을 보내지 않고 문장·4개 선택지만 제공한다. UI에서 가리는 것으로 답 노출을 막았다고 판단하지 않는다. CSV 내보내기는 개인정보 권한과 스프레드시트 수식으로 해석될 수 있는 값을 처리하고, 허용 필드만 출력한다.

### 4 3 시범 콘텐츠 공급과 교사 운영량

교재 순서 첫 10단어의 콘텐츠은행은 단어당 연습 객관 9개로 90개, 사전·사후·지연 측정 각 10개로 30개, 주간 전수 확인 20개, 월간 10개, 분기 10개를 준비하는 제작안이다. 객관 총 160개이며 작문 질문은 기본 전수 10개와 대체 상황 10개로 총 20개다. 정규 연습·측정·주간·월간·분기 문항을 서로 섞어 공급 충분이라고 계산하지 않는다.

가상 5 unknown·3 uncertain·2 known 조건에서 연습 공급은 45·27·18개, 6회 객관 활동 수요는 36·18·6개라 해당 조건은 공급할 수 있다. 첫 회차의 단어 수 분류 66조합(합계 10, 각 그룹 0–10)에서 미사용 연습 은행으로 10문항을 공급해야 한다. 모름 1·애매함 0·앎 9는 정규화한 9·0·1 배정으로 확인한다. 이는 이후 모든 동적 분류·반복 회차의 공급까지 보장하지 않는다. 교사 판정 변화로 소수 단어에 활동이 집중되어 적절한 미사용 새 문맥이 부족하면 이번 시범 운영은 보류·문항 보완으로 처리한다. 같은 연습 문항 재사용으로 60개 활동을 채우지 않는다. 일반 제품의 교사 승인 재배분 기능과 시범에서 계획한 60개 공급 가능 조건을 구분한다.

교사 시간은 학생 30명 × 2주당 초고 10개 × 초고 검토 건당 3분 = 900분에, 부모 메시지 120분을 더해 2주 1,020분·주 510분이라는 가정으로 재산정한다. 수정본 재확인·과제 준비·상담·출력 확인은 별도이며 실제 검토 시간을 파일럿에서 측정한다. 3버튼으로 배점 입력을 없앴더라도 검토 예산 3분이 실제로 줄었다고 간주하지 않는다. 이 작업량을 확인하기 전 기존 학생당 주 3분 검토 목표를 유지한다고 보고하지 않는다.

### 4 4 오류 발생 시

공개 문항의 오류 신고를 받으면 신규 배정을 보류하고 영향 활동·학생·보고서 범위를 확인한다. 미응답 활동은 검수된 버전으로 교체하거나 보류하고 변경 분모를 표시한다. 이미 응답한 활동은 원문 버전과 답안을 유지한다. 정답 기준 정정이 필요하면 원래 판정·새 판정·사유·적용 시각을 별도로 보존하고 재집계 결과는 새 보고서로 만든다. 조용히 과거 정답이나 PDF를 덮어쓰지 않는다.

## 5 의미 단어 매칭 진단과 계획 확정

왼쪽에는 교재 source_order 순서로 10개의 사전적 의미, 오른쪽에는 같은 연속 묶음의 단어 10개를 무작위로 제시한다. 단어를 드래그해 뜻 행에 놓거나 단어 클릭 후 뜻 행 클릭으로 배치한다. 키보드로도 같은 선택·이동을 수행한다. 현재 배치와 무작위 순서는 진단 세션에 저장해 뒤로가기·재접속 때 보존한다. 단어 토큰 한 개를 두 행에 동시에 배치할 수 없다.

각 의미 행에는 ‘모른다’가 있다. 선택 즉시 서버가 올바른 단어를 자동 배치하고 해당 행을 잠근다. 이 자동 답은 unknown이며 정답으로 맞힌 단어가 아니다. 자동 배치할 토큰이 다른 행에 있으면 그 행의 현재 배치를 비우고 이동 이유를 표시한다. 이전 배치·스냅샷은 보존하며 토큰을 복제하지 않는다. 미배치 null과 모른다는 다르다. 10개 모두 직접 배치 또는 모른다 처리된 뒤 진단 제출·계획 확인으로 진행한다.

### 5 1 진단 정답 공개와 채점

모른다 자동 답은 잔여 진단의 단서가 되므로 최초 정답 공개 직전에 **현재 10개 행 전체 배치 스냅샷**을 서버에 보존한다. 이후 모른다를 추가로 누르거나 배치를 수정해도 이 첫 공개 전 스냅샷을 바꾸지 않는다. 정답 공개 뒤 수정한 답의 최종 정답 여부보다 공개 전 배치를 진단 근거로 우선한다.

| 행의 근거 | 진단 분류 | 진단 독립 정답 집계 |
| --- | --- | --- |
| 정답 공개가 전혀 없는 상태에서 전체 제출한 직접 응답 | 알맞으면 known, 틀리면 uncertain | 직접 응답은 분모, 알맞은 응답은 분자 |
| 첫 공개 전 스냅샷에 직접 배치가 있는 행 | 원래 배치가 알맞으면 known, 틀리면 uncertain | 공개 전 원배치로 채점; 이후 변경답으로 다시 올리지 않음 |
| 공개 전 스냅샷이 null이고 공개 뒤 처음 놓은 행 | 알맞아도 uncertain + 재확인 필요 | 직접 응답은 분모, 노출 후 정답은 독립 분자 제외 |
| 모른다를 눌러 자동 답이 들어간 행 | unknown | 자동 답은 분자·분모 모두 제외 |
| 아직 비어 있고 모른다도 선택하지 않은 행 | 미응답 | 계획 확정 불가; unknown으로 자동 변환하지 않음 |

공개 전 원배치가 있더라도 모른다를 눌러 자동 답 처리한 행은 unknown으로 남긴다. 원배치와 이후 이동은 이력에 보존한다. 공개 후 답을 맞혀서 독립 진단 분류가 승격되지 않으며, 복습에서 새 문맥으로 다시 확인한다. 화면에는 ‘답이 공개된 뒤 맞힌 단어는 복습에서 한 번 더 확인해요’를 표시한다. 이 규칙은 사용자 요청의 즉시 자동 답을 유지하면서 진단 노출을 구분하는 상세 정책이다.

진단 데이터는 `diagnostic_session`, `random_order`, `placements_before_first_reveal`, `first_reveal_at`, `unknown_autoanswer_rows`, `placement_events`, `final_placements`, `diagnostic_group`, `independent_correct`, `exposure_flag`로 분리한다. 직접 배치 응답과 자동 답을 동일한 정답 이벤트로 저장하지 않는다. 서버에 첫 공개 전 스냅샷이 저장된 뒤 자동 답을 공개하며 저장 실패 때 정답을 공개하고 기록 완료로 표시하지 않는다. 요청 재전송은 같은 공개 이벤트·스냅샷에 연결한다.

뒤로가기의 진단 화면은 원응답·현재 배치·공개 이력·분류를 보존한 읽기/확인 상태다. 공개된 정답을 지우고 새로운 독립 진단으로 다시 채점하지 않는다. 새로운 진단이 필요하면 다른 승인 문항 세트·세션으로 명시적으로 배정하고 이전 결과를 남긴다.

### 5 2 배정용 이해 상태의 우선순위

`diagnostic_group`은 진단 당시 결과이며 `effective_group`은 다음 계획에 사용할 이해 상태다. 교사가 확정한 최신 다음 분류가 있으면 다음 객관 집중·보충 계획에 우선 사용한다. 교사 확정이 없으면 진단 결과와 이후 독립 수행에 근거한 잠정 상태를 사용한다. 새 객관 오답이나 수정본이 생겨도 이미 확정한 판정·근거를 자동으로 덮어쓰지 않고 재확인 필요를 표시한다.

교사 확정은 작문 3버튼 판정, 현재 묶음의 해당 단어 객관 첫 응답 집합, 시스템 자동 분류, 교사가 선택적으로 바꾼 수동 분류와 최종 분류로 구성한다. 별도 이해 상태 선택과 판정 이유 입력은 필수가 아니다. 기본 선택값은 자동 제안이고 수동 변경을 했다면 그 값이 우선한다. 이유·피드백·수동 변경 설명은 선택 입력이다. 학생 수정만으로 승격하지 않으며 최신 수정본은 교사 재확인 대기다. 의미 범위 교정 시 옛 판정을 무조건 승계하지 않고 교육 담당자가 적용 범위를 확인한다.

진단 결과·원배치·노출 기록·과거 확정 계획은 불변이다. 교사 판정이 바뀌어도 진행 중 과제의 6·3·1 할당량·문항·순서·배정 그룹을 바꾸지 않는다. 변경된 이해 상태는 다음 계획 생성에서 적용하고 왜 배분이 바뀌었는지 근거를 보여 준다. 학습 후·지연 재확인의 새 기록도 원진단을 덮어쓰지 않는다.

### 5 3 배분 알고리즘

배분 대상은 객관형 `regular_focus`와 객관형 `period_remedial` 활동이다. 의미 매칭 진단, 별도 `writing_coverage` 전수 작문 10개, `period_coverage`, 사전·사후·지연 측정은 60·30·10 분모에 넣지 않는다. 활동 수·단어 수·학습시간도 구별한다.

1. 목표 활동 수 N과 available 의미·승인 활동을 확인한다. 유효 그룹은 의미와 적절한 승인 활동이 있는 그룹이다.
2. 기본 가중치 unknown 0.6, uncertain 0.3, known 0.1을 유효 그룹에서 정규화한다.
3. 첫 계획은 각 `N × 정규화 가중치`의 정수 부분을 배정하고 남은 수를 소수 부분이 큰 그룹에 배정한다. 소수 부분이 같으면 unknown → uncertain → known 순으로 처리한다.
4. 그룹 내부에서는 미학습 단어, 복습 기한, 취약 의미를 우선하며 배정 이력으로 특정 단어 누락을 줄인다. 중심 의미 한 개에 서로 다른 승인 문맥을 배정할 수 있다.
5. 그룹의 실제 문항 공급이 할당량보다 적으면 가능한 활동을 배정하고 남은 수를 공급 가능한 그룹의 가중치로 다시 배분한다. 모두 부족하면 N을 줄이거나 과제를 보류하며 원래 요청 N, 최종 N, 변경 수·사유를 보여 준다. 같은 예문 복제로 채우지 않는다.
6. 계획에 의미·활동 버전·4개 선택지와 문항 순서·배정 그룹·그룹 근거 판정 버전·목표 가중치·정수 보정·공급 부족·배분 정책 버전을 고정한다. 확정 후 상태 변경은 다음 계획에만 적용한다.

연속 회차 정수 편차는 아래 정책으로 구체화한다. 이는 팀의 승인 검토용 산식이며 실서비스 검증이 완료된 것은 아니다. 유효 그룹 G와 정규화 가중치 w, 이전 편차 credit, 공급 상한 capacity를 입력한다. 가능한 그룹·가중치 정책이 같고 적절한 승인 공급이 충분할 때 편차를 이어 쓴다. 그룹·가중치 정책이 달라졌거나 공급 상한이 배분을 제한하면 credit을 0으로 초기화하고 사유를 기록한다. 문항 ID가 새 문맥으로 바뀌는 것 자체는 초기화 사유가 아니며 공급 제약 여부를 기준으로 한다.

```text
입력: N(0 이상의 정수), 유효 그룹 G, 가중치 w(합계 1), 이전 credit(합계 0)
기본 편차: 같은 G와 정책·공급 충분 조건이면 이전 credit, 아니면 0
target[g] = N × w[g] + credit[g]
q[g] = floor(max(0, target[g]))

sum(q) > N인 동안:
  q[g] > 0인 그룹 중 q[g] - target[g]가 가장 큰 그룹의 q를 1 감소
  동률은 known → uncertain → unknown 순으로 감소
sum(q) < N인 동안:
  target[g] - q[g]가 가장 큰 그룹의 q를 1 증가
  동률은 unknown → uncertain → known 순으로 증가

승인 공급 상한 때문에 q를 충족할 수 없으면:
  credit 초기화와 공급 부족 사유 기록 후 기본 가중치로 다시 계산
  q[g]를 capacity[g]까지 배정하고 남은 수를 공급 여유 그룹에서 재정규화·정수 배분
  남은 공급도 없으면 N_final을 실제 배정 수로 축소하거나 전체 과제를 보류
  이 회차 다음 credit은 0; 부족 때문에 생긴 미배정 수를 미래 반복으로 강제 상환하지 않음
그 외:
  actual[g] = q[g]
  next_credit[g] = credit[g] + N × w[g] - actual[g]
```

첫 회차에는 credit=0이므로 일반 최대 나머지 정수 배분과 같다. 음수 target을 실제 음수 활동 수로 배정하지 않는다. 합계 보정은 각 반복에 합계를 한 개씩 N에 가깝게 만들어 종료한다. 최종 q는 음수 없이 합계 N이며 공급 제약 회차는 요청 N과 실제 N을 구분한다. 공급 충분 회차의 credit 합계는 0이다. 가중치·편차는 유리수 또는 고정 정밀도 십진수로 계산하고 비교 허용 오차·동률 규칙을 고정해 부동소수점 때문에 우선순위가 바뀌지 않게 한다. 비중을 맞추려고 무관한 문맥이나 같은 예문을 반복시키지 않는다.

| 입력 예시 | 첫 계획 기대값 | 유의점 |
| --- | --- | --- |
| 세 그룹 존재, N=10, 편차 없음 | 6·3·1 | 진단 결과 단어 수 5·3·2와 구분 |
| 모름 없음, N=10 | 0·8·2 | 목표 0·75·25%, 다음 동일 조건 회차는 편차 반영 0·7·3 |
| 한 그룹만 있음 | 그 그룹 N개 | 존재하지 않는 의미·문항을 만들지 않음 |
| 세 그룹 존재, N=3 | 2·1·0 | 이상값 1.8·0.9·0.3에서 정수 보정 |
| 세 그룹 존재, N=1 반복 | 첫 unknown, 다음 uncertain, 세 번째 unknown | 세 번째 target은 0.8·−0.1·0.3; 음수 uncertain 배정은 0. 같은 조건 10회 합계 6·3·1 |
| 승인된 적절한 활동 없음 | 배정 보류 | 0/0을 0%·100%로 표시하지 않고 계산 불가 표시 |

계획 생성은 멱등 키와 트랜잭션으로 중복 생성을 막는다. 확정 계획 변경은 취소·교체 사유와 새 계획 버전으로 처리하고 학생이 응답한 활동을 삭제하지 않는다.

## 6 응답 작문 저장 상태

### 6 1 객관 집중과 전수 작문

객관 집중학습은 10문항을 섞어 제시하고 각 문항은 문장의 빈칸과 4개 선택지를 갖는다. 풀이 전에 중심 목표 단어 제목·뜻풀이를 따로 제공하지 않는다. 선택지에 있는 단어들은 비교 대상으로 보이며 정답만을 사전 힌트로 강조하지 않는다. L1–L3는 문장 길이·읽기 보조·작문 틀로 조절하고 이번 기본 객관 흐름은 모두 4지선다로 통일한다. 문항과 선택지의 최초 무작위 순서는 계획에 고정해 뒤로가기에서 바뀌지 않는다.

`writing_coverage`는 교재 source_order 순서로 배운 10단어 각각 한 문장을 쓰는 별도 전수 과제다. 한 묶음에서 10개 초고를 한 번씩 제출하며 60·30·10 객관 활동 할당량에 넣지 않는다. 작문은 5개씩 나눠 저장할 수 있지만 전체 완료 조건은 10개 유효 초고다. 초고 10개 완료 뒤 교사 검토 대기와 관계없이 복습으로 이동한다. 검토 대기 중 작성해 둔 답안이 사라지거나 다시 제출하도록 초기화하지 않는다.

2주·6회 시범 운영 가정에서 객관 활동은 10개 × 6회 = 60개, 전수 작문은 별도 10개이므로 합계 70개다. 진단·간격/기간 복습·사전/사후/지연 측정은 이 70개 밖에서 단계별로 계산한다. 이전 ‘54개 객관 + 6개 초고 = 60개’ 가정은 폐기한다. 실제 운영 시간과 교사 10개 초고·수정 검토 시간을 다시 산정하며 10문장 작문을 15분 안에 완료한다고 약속하지 않는다.

한 배정 활동은 `assignment_activity_id`와 중심 `meaning_id`를 가진다. 비교 문항의 보조 단어는 중심 목표 활동 수나 배분 그룹을 늘리지 않는다. 새로 배정한 다른 문맥은 새 활동이며 같은 문항의 재시도·힌트·작문 수정은 기존 활동 이력이다.

| 상태 | 진입 조건 | 완료·평가 처리 |
| --- | --- | --- |
| assigned | 확정 계획에 배정됨 | 미응답 |
| in_progress | 답안 편집·힌트 확인 중 | 완료 활동으로 세지 않음 |
| submitted | 유효 객관 응답 또는 초고 제출이 서버 저장됨 | 제출 완료로 한 번 계산. 오답도 수행 완료 |
| review_pending | 작문 초고 제출 후 | 평가 없음. 0점·통과로 자동 표시하지 않음 |
| reviewed / revision_requested | 교사가 해당 제출본을 평가함 | 3버튼 판정·선택 의견·다음 행위 표시 |
| revised | 학생이 수정본을 제출함 | 수정 이력, 필요 시 재검토. 완료 활동 수는 그대로 |
| held / cancelled | 사유와 운영자·시각이 기록됨 | 과제 분모 변경은 버전·이유와 함께 표시 |

객관 응답 완료, 전수 작문 10개 제출 완료, 표현 평가 확정, 수정 완료는 독립 필드로 관리한다. 학생이 초고 제출 뒤에도 수정할 수 있지만 교사 평가의 대상 제출본 ID를 유지한다. 수정본이 도착한 동안 교사가 옛 초고를 평가하면 옛 제출본 평가임을 표시하고 새 제출본은 미검토로 남긴다.

### 6 2 첫 응답 도움 중복 방지

객관형의 `first_attempt`는 서버가 최초 수락한 유효 제출이다. 빈 답·형식 오류·저장 실패는 유효 제출이 아니다. 이후 정답을 맞혀도 첫 응답은 바뀌지 않는다. 힌트 요청은 서버 이벤트로 먼저 기록하며 첫 응답 전에 도움을 받은 문항은 독립 정답 분자에 넣지 않는다. 첫 응답 후 도움은 첫 응답의 독립성을 소급해 바꾸지 않는다.

힌트를 읽는 시간과 응답 업로드 순서가 뒤집히지 않도록 동일 세션의 순서를 기록하고 필요하면 해당 활동을 도움 사용으로 보수적으로 표시한다. 답·해설은 유효 제출 뒤 공개한다. 측정 문항에는 승인된 평가 정책에 따라 도움·해설 공개 시점을 제한하고 일반 연습과 별도 단계에 저장한다.

`client_submission_id` 멱등 키와 `assignment_activity_id + attempt_number` 고유 제약으로 네트워크 재전송·더블 클릭을 한 번만 수락한다. 재시도 이벤트는 기존 활동에 추가되며 활동 완료 수·복습 고유 진도를 늘리지 않는다.

### 6 3 작문 3버튼 판정과 다음 분류

초고는 자연스러운 활용형을 허용하고 목표 단어 포함 여부만으로 정답 처리하지 않는다. 교사는 뜻에 맞는 사용·상황·문장 성립을 관찰 안내로 참고하되 항목별 점수를 입력하지 않는다. 판정은 정답(correct)·오답(incorrect)·검토(애매)(uncertain) 중 하나를 반드시 선택하는 방식이다. 버튼은 상호 배타적 단일 선택이며 선택된 버튼을 다시 눌러 비우는 토글이 아니다. 미선택 null은 미검토이며 애매 판정과 다르다. 코멘트는 선택 입력이고 없어도 확정할 수 있다.

자동 분류 규칙 버전 제안은 `writing-understanding-v3-1`이다. 판정할 작문과 같은 현재 묶음에서 해당 단어가 중심 목표인 유효 첫 객관 응답 ID 집합을 확정 시점 스냅샷으로 얻는다. 진단 매칭·자동 답·재시도·이전 묶음 응답은 이 근거에 넣지 않는다. 객관 근거가 여러 개면 모두의 첫 응답을 확인한다. 첫 오답 뒤 재시도 정답은 원첫답 오답으로 남긴다.

| 작문 판정 | 현재 묶음의 관련 객관 첫 응답 | 자동 제안 |
| --- | --- | --- |
| 오답 | 근거 여부·정오와 관계없이 | unknown 모름 |
| 검토(애매) | 근거 여부·정오와 관계없이 | uncertain 애매함 |
| 정답 | 유효 첫 응답 1개 이상이며 모두 정답 | known 앎 |
| 정답 | 유효 첫 응답 중 오답 1개 이상 | uncertain 애매함·객관 재확인 |
| 정답 | 관련 유효 첫 객관 응답 없음 | uncertain 애매함·객관 근거 없음 |

힌트 사용은 위 known 자동 제안의 차단 조건이 아니다. 힌트 후 첫 정답+작문 정답도 known을 제안하되 ‘도움 사용’ 근거를 함께 표시한다. 교사는 그 근거를 보고 다음 분류를 uncertain 등으로 수정할 수 있다. 독립 정답률에서는 첫 응답 전 힌트를 사용한 정답을 분자에서 제외하며 배정용 known과 독립 수행·숙달 판정을 혼동하지 않는다.

화면의 다음 분류 선택값은 자동 제안으로 채운다. 교사는 필요할 때 known/uncertain/unknown으로 수정하고 확정한다. 수동 변경·변경 이유는 선택이며 최종 값은 manual_group이 있으면 그 값, 없으면 auto_group이다. 다시 자동값을 선택하면 수동 변경을 해제하고 그 상태를 이력에 남길 수 있다. 시스템 근거 문구는 작문 판정, 관련 첫 응답 수·정오·도움 사용·근거 없음·수동 변경 여부를 설명한다. 선택 코멘트를 시스템 근거 대신 필수 입력하게 하지 않는다.

근거 스냅샷에는 snapshot_id/version, rule_version, current_bundle_id, meaning_id, writing_submission_version_id와 본문 해시, objective_first_item_ids·첫 응답 정오·힌트 노출, writing_judgment, auto_group, manual_group, final_group, system_reason, optional_comment, optional_override_reason, teacher_id와 confirmed_at을 고정한다. 새 객관 응답이나 수정본이 들어와도 옛 확정 스냅샷을 재계산하지 않는다. 새 수정본은 재확인 대기이며 교사가 해당 본문을 다시 판정·확정한 새 버전만 이후 계획에 적용한다.

기존 배점 grade는 legacy로 보존한다. 이미 교사가 명시적으로 확정한 옛 understanding group은 기존 확정 이력·효력으로 유지하고 레거시 출처를 표시한다. 이를 새 3버튼 판정으로 복사하거나 배점에서 자동 환산하지 않는다. meaning/context/sentence의 숫자나 합계를 새 정답·오답·검토(애매)로 자동 환산하지 않는다. 이전 진단·객관 첫 답·초고·수정본 저장도 삭제하지 않는다. 새 판정 레코드는 새 정책 버전으로 저장하고 과거 배점만 있는 문장은 ‘재판정 필요’로 표시한다. 리포트의 뜻 이해·문맥 추론·작문 활용·학습 태도 정성 의견은 문장별 3버튼 판정과 별도다. 미검토 작문은 참여·초고 제출에 포함하되 교사 확인 정답 성과에 넣지 않는다.

### 6 4 자동 저장과 연결 끊김

작성 중 / 저장 중 / 서버 저장 완료 시각 / 연결 끊김·미전송 / 저장 실패·재시도 상태를 구분한다. 서버의 성공 응답 전에 ‘저장 완료’라고 표시하지 않는다. 초안에는 `revision_number` 또는 ETag를 사용해 다른 탭의 오래된 답안이 최신 답안을 덮어쓰지 않게 한다. 충돌 시 학생에게 복구 가능한 두 초안을 제시한다.

교사 판정 초안은 평가 대상 제출본 ID별로 구분한다. 선택한 작문 버전을 바꿨다가 돌아와도 판정·코멘트·수동 다음 분류를 복원하고, 미확정 초안으로 이전 확정 근거를 덮어쓰지 않는다. 객관 재시도 편집 여부와 미제출 선택도 해당 활동 응답에 연결해 뒤로가기·재진입에서 보존한다.

각 화면에 뒤로가기를 제공한다. 학생은 진단 → 계획 → 객관 → 전수 작문 → 복습 사이에서 자신의 저장 상태를 되돌아 확인하고, 교사는 목록 → 제출본 검토 → 리포트 편집 → PDF 미리보기 사이에서 선택 학생·기간과 작성 문구를 보존한다. 뒤로가기로 첫 응답·초고·교사 판정·복습 진도를 지우거나 활동 완료 수를 늘리지 않는다. 제출한 문항은 기존 첫 응답·해설을 보여 주며 새 문항처럼 재채점하지 않는다. 미저장 편집이 있으면 저장/나가기 동작과 상태를 안내하고 역할 전환·로그아웃과 일반 뒤로가기를 구별한다. 브라우저 뒤로가기·화면 내 뒤로가기 모두 같은 권한·상태 규칙을 적용한다.

서버 저장본은 재접속 시 복구한다. 브라우저 내 임시 초안을 쓰는 경우 계정·학원·활동별로 구분하고 공용 기기 전환 시 종료 정책을 적용한다. 미전송 답안을 서버 제출·기간 실적으로 계산하지 않는다. 최소 납품 기준은 서버 저장 확인과 복원이며, 오프라인 제출·동기화는 별도 범위를 정한다.

시제품 저장 형식은 v2를 유지한다. 복원 전에 중첩 배열·객체·그룹·응답·인덱스·제출본 참조와 확정 보고서 형식을 검사한다. 손상 원문은 격리·내보내기 대상으로 보존하고 유효한 기존 기록을 최대한 복원한다. 파싱 실패를 빈 기록으로 조용히 덮어쓰지 않는다. 호스트 공유 상태는 revision·수정 시각으로 최신 로컬 편집과 비교한 뒤 수신하며 오래된 상태·동률·판단 불가 충돌은 최신 입력을 덮어쓰지 않는다. 손상 원문의 별도 보존이 실패하면 기본 저장값을 덮어쓰지 않는다. 신규 문항은 활동에 내용·정답 스냅샷을 고정하고 과거 콘텐츠는 이전 계획 재현에만 사용해 콘텐츠 개선으로 저장 답안의 정답 기준이 달라지지 않게 한다. 로컬 저장과 호스트 저장의 성공·실패를 독립적으로 표시하고 다음 저장이 성공하면 해당 실패 경고만 해제한다. 데이터로 만든 HTML 속성값도 이스케이프하고 참조 ID를 검증한다. 이는 모의 저장 정책이며 서버 권한·실제 다중 기기 동기화 검수를 대체하지 않는다.

## 7 간격 복습과 기간 전체 복습

### 7 1 간격 복습

단어별 다음 날·3일·7일·14일 복습은 초기 정책이다. 기준 학습 시점, 결석·오답 조정, 교사의 하루 상한 변경과 사유를 기록한다. 7일 지연 측정은 각 의미의 마지막 학습·연습 노출 이후 최소 7일을 확인한다. 그 사이 복습으로 다시 노출됐으면 실제 경과를 기록하고 지연 측정 일정을 다시 잡는다. 달력 주간 복습과 7일 경과 측정을 같은 것으로 계산하지 않는다.

### 7 2 대상 집합과 기간

기간은 Asia/Seoul로 계산하고 시작 포함·끝 제외 구간을 사용한다. 주간은 월요일 00:00–다음 월요일 00:00, 월간은 1일 00:00–다음 달 1일 00:00, 분기는 1–3월·4–6월·7–9월·10–12월이다. 윤년·28/29/30/31일·연말 분기 전환도 같은 달력 규칙으로 처리한다. 저장 시각은 UTC이며 표시·기간 경계는 KST다.

실제 학습 집합은 그 기간에 유효 응답·작문 초고가 서버 저장된 활동의 중심 `meaning_id`를 중복 제거한다. 정규 연습, 보충과 실제 복습 활동을 포함하며 의미 매칭 진단·뜻 열람·등록만 한 의미는 제외한다. 전수 작문의 유효 초고가 제출된 10개 중심 의미는 교사 검토가 아직 없어도 실제 학습 집합에 포함한다. 사전·사후·지연 측정만 한 의미는 측정 표본으로 따로 두고 학습 집합을 늘리지 않는다. 다른 단어와 비교할 때 등장한 보조 단어도 자동 포함하지 않는다. 오답·도움 사용·작문 검토 대기는 실제 수행이므로 포함한다.

기간 진행 중 대상은 집계 시각을 표시한 예정 집합이다. 실제 배정 시 `review_set_version`과 대상 의미 ID·근거 활동·기준 시점을 고정한다. 진행 중 응답으로 분모를 매번 바꾸지 않는다. 기간 종료 후 확정 버전과 이후 정정·추가 버전을 구분한다. 기간 경계에 실제 늦게 제출된 응답은 서버 수락 시각의 기간에 포함하고, 과제 완료율은 원래 과제 대상에 연결한다. 원기간 대상이 늘어나는 경우는 기준 시점 이후 도착한 해당 기간의 수락 기록·허용된 기록 정정이며, 단순 과제 예정일만으로 원기간 학습 집합에 옮기지 않는다.

### 7 3 전수 확인과 보충

`period_coverage`는 모든 대상 의미에 승인된 새 문맥 활동을 최소 1개 배정한다. known 의미도 포함하고 60·30·10을 적용하지 않는다. 객관형 확인을 기본으로 하며 작문 확인을 쓰면 해당 초고 첫 제출이 확인 진도이고 교사 확인은 별도다. 특정 의미에 적절한 승인 확인 문항이 없으면 해당 단어를 없애거나 진도 완료로 표시하지 않고 콘텐츠 보완 대기로 남긴다.

전수 확인 진도 = 유효 첫 응답을 제출한 고유 대상 의미 수 ÷ 해당 버전 대상 의미 수. 틀린 응답도 확인 진도에는 포함하되 독립 정답은 별도다. 반복 제출은 한 번만 증가한다. 대상 없음은 ‘해당 기간 실제 학습 어휘 없음’으로 표시하며 100% 학습 성취로 표현하지 않는다.

5–10개 단위의 청크, 교사가 정한 시작일·마감일·하루 상한, 저장·이어서 진행을 지원한다. 전수 확인 완료 뒤에만 객관형 `period_remedial`을 생성하고 최신 교사 확정 이해 판정을 우선한 배정용 상태로 60·30·10을 적용한다. 모든 학습 어휘의 전수 대상은 이해 판정과 관계없이 유지하며 known·uncertain·unknown 중 어느 그룹도 누락하지 않는다. 승인 문항 부족이면 일반 제품에서는 교사 승인 변경·재배분 사유를 표시하고, 이번 시범의 고정 활동 공급이 부족하면 보류·문항 보완으로 처리한다. 교사는 취약 어휘에 정규 보충을 먼저 배정할 수도 있지만 그것을 전수 확인 후 보충 완료로 대신 계산하지 않는다.

### 7 4 대상 버전 변경과 중첩 운영

새 대상 버전이 만들어지면 유지된 의미의 확인 답안은 기존 활동에 연결해 진도를 이어 쓰고 추가된 의미는 미확인으로 넣는다. 빠진 의미와 변경 사유도 남긴다. 이전 버전의 분모·진도·PDF는 보존한다. 예: v1 10개 중 6개 → 새로운 의미 2개 추가한 v2는 12개 중 6개이며 ‘2개 추가’를 표시한다.

주간·월간·분기 대상과 완료는 각각 유지한다. 같은 응답을 서로 다른 복습의 완료로 몰래 재사용하지 않는다. 운영표에서 여러 날로 나누거나 교사가 마감일을 조정할 수 있다. 다른 기간의 확인까지 대체하는 정책이 필요하면 대상·문항·조건·버전·보고서 표기를 별도 승인한 뒤 명세를 변경한다. 현재 제안은 각 기간에 새 문맥을 배정하는 방식이다.

의미 매칭 진단 / 객관 정규 집중학습 / 10단어 전수 작문 / 기간 전수 확인 / 객관 기간 보충 / 단어별 간격 복습 / 사전·사후·지연 측정을 별도 단계 필드와 카운터로 보존한다. 전체 수행량은 단계별 합계와 고유 의미 수를 함께 보여 주고 같은 수행을 여러 단계에 중복 합산하지 않는다.

## 8 교사 평가 리포트 출력

### 8 1 집계 규칙

| 지표 | 정의 | 예외·표시 |
| --- | --- | --- |
| 과제 완료율 | 예정 학습일이 기간 내인 유효 배정 활동 중 기준 시점까지 제출 완료한 수 / 같은 배정 활동 수 | 완료된 늦은 과제는 원래 과제 집합에 귀속. 취소·보류와 변경 분모 공개 |

집계 필터는 학원·반·학생·단계·일간/주간/월간/분기 또는 사용자 지정 기간이다. 반 자료는 학생별 진도와 반 고유 의미 합집합을 구분한다. 한 학생의 과제 분모에 다른 학생이나 다른 기간의 수행을 넣지 않는다. 분모 0·미응시·미평가는 0점으로 치환하지 않는다.

교사 확인이 늦어도 작문은 원래 활동·제출본에 연결한다. 보고서에는 활동 시점, 평가 시점, 데이터 기준 시점을 함께 둔다. 이후 확정·교정 데이터는 새 집계·PDF 버전으로 만들며 기존 내보낸 파일은 변경하지 않는다.

### 8 2 확정 평가 도넛과 비교

두 도넛은 동일 보고서의 대상 고유 meaning_id 집합을 분모 N으로 삼는다. 기간 필터·묶음·학생·기준 시각·대상 버전을 표시한다. 원문 중복 위치는 교육과정에서 보존하고 차트에서는 승인된 같은 의미 ID를 중복 제거한다. 데모의 초안 의미 ID와 가상 기록을 실제 교육 승인·달력 집계로 표현하지 않는다.

| 도넛 | 범주 | 집계 우선순위 |
| --- | --- | --- |
| 단어 이해 | 아는 단어·애매한 단어·모르는 단어·교사 확인 대기 | 기준 시각 이내 해당 의미의 최신 교사 확정 final_group. 기존 명시 확정 레거시 group은 인정. 교사 확정이 없으면 대기 |
| 작문 평가 | 정답·오답·검토(애매)·평가 대기 | 기준 시각 이내 해당 의미의 최신 확정 3버튼 writing_judgment. 숫자 배점만 있거나 확정 판정이 없으면 대기 |

진단·객관 수행 자동 제안은 기존 단어표와 배정 상태에서 사용하고 확정 도넛에 교사 확인 결과처럼 넣지 않는다. 새 수정본이 미확정이어도 이전 확정 결과를 차트에 유지하고 별도 revision_pending 의미 집합·개수·본문 버전을 표시한다. 대기 수정본 수를 도넛 분모에 더하거나 같은 의미를 두 범주에 세지 않는다. legacy_numeric_only는 작문 대기와 재판정 필요 근거로 관리하며 숫자에서 정오를 추론하지 않는다.

각 범주의 개수 c와 비율 c/N을 범례·텍스트로 제공하고 중앙 또는 인접 텍스트에 전체 N개를 표시한다. 범주 개수 합계는 N이다. 실제 비율로 SVG 각도를 계산하고 표시 비율만 소수점 한 자리로 반올림한다. 반올림 합계 차이는 100%로 강제 보정하지 않는다. N=0이면 빈 상태와 모든 개수 0을 표시하고 비율은 계산 불가(—)로 제공한다. N>0인 0개 범주는 0%로 표시한다.

정규 객관 진도는 유효 첫 제출 완료 활동/해당 정규 객관 배정 활동, 전수 작문 진도는 초고 제출 대상 고유 의미/전수 작문 대상 고유 의미로 따로 표시한다. 작문 제출 완료는 교사 평가 완료가 아니다. 추가 복습 목록은 교사 확정 애매·모름과 객관 재확인 근거를 보여 주며 재검토 대기는 별도 표시한다. 목록은 기존 전체 복습 대상의 범위를 줄이지 않는다. 교사 종합평가·부모 메시지와 60·30·10 배정 설명은 유지하며 도넛 결과 비중과 구분한다.

chart_snapshot에는 snapshot_id/version, report_scope, student_id, target_meaning_ids, target_hash, as_of, metric_rule_version, 이해·작문 범주별 count와 denominator, source_confirmation_ids, revision_pending_ids, legacy_pending_ids를 고정한다. 이전 자료 비교는 현재와 같은 대상 해시·규칙·학생 범위의 이전 교사 확정 스냅샷이 있을 때만 한다. 비교 문구는 ‘이전 확정 자료 대비’이며 두 기준 시각·버전을 표시한다. 조건이 맞지 않거나 이전 자료가 없으면 비교 자료 없음이다. 새 수정본이나 새 답안으로 옛 스냅샷을 변경하거나 지난주 자료를 자동 생성하지 않는다. 데모에는 실제 달력 기간 리포트가 없음을 표시한다.

SVG는 viewBox로 반응형 크기를 제공하고 인쇄 시 색·선·범례·텍스트가 함께 남아 잘리지 않아야 한다. 앱 인쇄 버튼과 브라우저의 일반 인쇄(Ctrl+P) 모두 인쇄 직전에 현재 대상의 부모 자료를 다시 생성해 빈 인쇄 영역이나 이전 자료를 출력하지 않도록 한다. 확정 문구·내부 메모 제외 규칙은 동일하게 적용한다. 차트 대체 설명과 의미별 텍스트 표를 제공해 색만으로 범주를 구별하지 않게 한다. 저장 PDF의 차트·목록·교사 문구는 같은 보고서 스냅샷에 연결한다. 실제 서비스·인쇄 검수는 구현 뒤 실행하며 현재 교육 승인과 실서비스 QA는 미완료다.

### 8 3 교사 의견

리포트 항목은 뜻 이해·문맥 추론·작문 활용·학습 태도다. 각 항목에 `우수 / 안정 / 연습 중 / 추가 지도 / 미평가`, 근거 답안 또는 관찰, 작성 교사를 입력한다. 학습 태도는 실제 관찰을 근거로 하며 접속 횟수·정답률로 자동 확정하지 않는다.

강점·보완점·다음 지도 계획의 종합평가와 ‘부모님께 전하는 말’을 자유롭게 작성한다. 예시 문구를 불러오더라도 교사 확인 전 실제 관찰로 취급하지 않는다. 내부 지도 메모는 교사용 필드로 관리하고 부모 PDF 출력 모델에 포함하지 않는다. 필요한 내용은 교사가 공개 메시지에 별도로 작성해 미리보기에서 확인한다.

의견 상태는 `draft → teacher_confirmed`다. 작성·수정·확인 시각, 담당 교사, 항목별 공개 선택과 서명을 보존한다. 수정하면 새 의견 버전으로 바뀌고 재확인한다. 초안 미리보기는 초안 표시를 하며 최종 PDF 생성에는 교사 확인 상태와 대상 학생·기간 재확인이 필요하다.

| 학부모 전달 | 한 학생의 일간·주간·월간 PDF, 학원명·로고·기간·지표·확인 작문·교사 의견·복습 계획 | 교사가 대상·기간·포함 문구·내부 메모 제외를 미리보기에서 확인한 뒤 다운로드 |
| 교사 운영 | 담당 학생·반 CSV와 운영 보고서 | 서버가 학원·담당 반 권한과 필드 범위를 검사 |
| 홍보 검토 | 별도 익명 요약, 기간·표본 수·분모·방법·한계 | 공개 목적·범위 확인 기록. 개인 사례·작문 인용은 별도 확인 |

학생별 묶음 출력은 학생마다 독립된 파일로 생성한다. 반 CSV를 부모용 개인 PDF로 그대로 내보내지 않는다. 1–2쪽 부모 요약을 기본으로 하며 월간·분기 단어가 많아도 목록을 조용히 누락하지 않는다. 요약에는 전체 대상·확인·미확인 수와 대표 어휘를 표시하고 ‘전체 목록은 별첨’ 여부를 명시해 해당 학생의 부록으로 출력한다. 분기는 복습 결과 요약 출력이며 월간 리포트와 같은 이름으로 섞지 않는다.

PDF 생성 작업은 요청 시 보고서 스냅샷을 고정하고 비동기 작업으로 처리한다. 대기·생성 중·완료·실패·재시도를 표시한다. 파일 다운로드 때도 요청자의 현재 권한을 확인하고 파일 주소를 다른 학생에게 공개하지 않는다. 서명된 다운로드 주소를 쓰면 짧은 유효기간과 학생별 범위를 적용한다. 장애 후 재시도도 같은 요청 버전에 연결한다. 실제 발송·외부 게시 기능은 현재 범위에 없다.

## 9 기술 구조 제안

프레임워크는 팀 인력·유지보수 역량·호스팅 조건을 확인한 뒤 결정한다. 다음 계층과 책임은 견적에 포함한다.

| 계층 | 책임 | 주요 작업 |
| --- | --- | --- |
| 학생·교사 웹 화면 | 별도 진입과 역할별 동작, 키보드·터치·작은 화면 대응 | 선택·문항·작문·검토·복습·리포트 화면 |

개발·검수·실운영 환경을 분리한다. 시제품은 가상 데이터로 동작하며 로컬 저장도 서버 저장과 구별한다. 계약에 사용할 성능 수치·동시 사용 인원·복구 목표·지원 시간은 실제 환경 측정과 운영 조건을 근거로 확정한다. 기존 95% 화면 2초·100명 동시 사용은 검증 목표이며 보장 실적이 아니다.

## 10 구현 순서와 검수 준비

1. 교육 콘텐츠 10개 완성 묶음·2주 운영표·권한·집계 예시를 먼저 맞춘다. 콘텐츠 승인과 실제 학원 운영조건은 별도 확정 과제로 관리한다.
2. 클릭 시제품에서 학생 시작·타이핑·단서 이해와 교사 검토·부모 글 작성·출력을 관찰한다. 시제품에 실제 보안·저장 검수를 했다고 표시하지 않는다.
3. 승인 콘텐츠 등록부터 한 학생 학습→교사 평가→수정→전체 복습→개인 PDF까지 통합 구현한다. 인증·답안 보존·권한·분모를 이 흐름에 포함한다.
4. F01–F26 수용표의 정상·실패·경계 사례를 테스트한다. 모든 항목은 현재 ‘미실행’이며 구현 뒤 증거와 담당자를 붙인다.
5. 실제 환경에서 백업 복원, 동시 사용, 저장 실패·PDF 재시도, 공용 기기 전환을 확인한 뒤 4주 파일럿을 운영한다. 분기 기능은 3개월치 시험 기록으로 검수하고 실제 분기 학습 결과는 운영 기간이 쌓인 뒤 평가한다.

검수 문서: `planning/acceptance-matrix.csv`는 F01–F26 모두에 구현·실패 사례·기대 결과·검증 방법을 연결한다. `planning/work-breakdown.csv`는 작업·의존성·담당 역할·산정 입력·검수 ID를 연결한다. 고정 가격·인력일·완료 날짜를 추정 실적으로 채우지 않는다.

## 11 견적과 계약 준비

견적 입력은 도입 학원·반·학생·동시 사용자 수, 기기·브라우저, 승인 의미·문항 수와 L1–L3 변형 수, 작문 제출·교사 검토량, 복습 중첩량, PDF·CSV 출력량, 학원별 맞춤 범위, 계정·복구·지원 시간, 보관 기간·복구 목표다. 개발비·콘텐츠 제작비·월 운영비를 분리한다.

개발 계약에는 F01–F26 구현·검수 범위, 콘텐츠 최종 승인 책임, 납품·파일럿 조건, 변경 절차, 소스·콘텐츠 권리, 하자 대응·유지보수, 기록 내보내기·종료 처리, 비용·일정을 명시한다. 개발팀은 작업량·선행 조건·운영비를 제시하고 사용자에게 프레임워크나 DB 제품 선택을 떠넘기지 않는다.

실제 개발 착수 판단은 상세 명세·검수표·승인 콘텐츠 제작계획·견적·운영 조건을 한 묶음으로 확인하는 시점에 한다. 지금 자료의 완료는 그 판단을 구체화하기 위한 준비이며 생산 서비스의 공개·실제 학생 데이터 수집 완료를 뜻하지 않는다.
