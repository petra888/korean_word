# 테스트 배포 준비와 진행 순서

2026년 10월 4일. v5 QA 개선 후 배포 전 추가 점검에서 보기 순서 복구 결함을 보완한 v5.1 시제품을 기준으로 한다. 아래 규모와 일정은 권장안이며 학원 확정 조건이 아니다.

## 1. 현재 가능한 테스트

| 구분 | 준비 상태 | 테스트 목적 |
| --- | --- | --- |
| 교직원 가상 데이터 데모 | 검증된 정적 HTML과 배포용 폴더·ZIP 준비 | 학생·교사 모의 흐름, 작문 판정, 리포트·인쇄와 기기 사용성 검토 |
| 실제 학생 파일럿 | 계정·권한·서버 저장·달력 집계 구현 필요 | 학생별 학습 기록을 교사가 모아 검토하고 기간별 보고서를 제공 |

현재 학생/교사 전환은 모의 화면이고 저장은 해당 주소·기기·브라우저의 저장소에만 남는다. 교사와 학생이 다른 기기로 같은 학생 기록을 공유하는 기능은 구현되어 있지 않다. 실제 일간·주간·월간 집계와 복습 날짜 자동 배정도 개발 범위다. 실서비스 검수63사례는 미실행이다.

추가 수정은 손상된 저장값에 같은 보기 ID가4번 들어갔을 때 정답이 사라지는 복구 누락이다. 보기 ID 전체의 중복 없는 순열을 검사하고, 손상 원문을 격리한 뒤 보기 순서만 다시 만든다. 학생의 답안·작문·교사 판정·과거 문항 스냅샷은 유지한다. 근거는 [추가 수정 설명](../qa/release-readiness/choice-order-fix.md)과 [최종 검증 결과](../qa/release-readiness/validation-summary.json)에 있다.

## 2. 우선 진행할 교직원 데모 배포

| 순서 | 할 일 | 담당 | 완료 조건 |
| --- | --- | --- | --- |
| 1 | 수정본을 검토해 커밋·푸시하고 배포 기준 버전을 고정 | 개발 담당 | 배포 기준 커밋·HTML 해시 기록, 이전 배포본 보관 |
| 2 | 동일 소스로 배포 폴더·ZIP 재생성 | 개발 담당 | 현재 HTML과 검증 결과·index.html의 해시 일치 |
| 3 | 교직원만 열 수 있는 HTTPS 테스트 주소 준비 | 개발·계정 관리자 | 허용된 교직원은 접속되고 접근 제한이 실제로 동작 |
| 4 | 실제 학원 기기에서 가상 학생으로 수업 흐름 검토 | 담당 교사·기획 | 아래 기기 검사표에 결과·재현 방법·증거 기록 |
| 5 | 발견한 결함 수정 후 해당 경로 재검사 | 개발·QA | 학습 차단·입력 손실·잘못된 채점·출력 누락 해소 |

커밋·소스 전달·배포의 실제 완료 여부와 주소는 별도 진행 기록으로 관리한다. 이 문서와 배포 ZIP의 준비만으로 외부 배포가 완료된 것으로 처리하지 않는다. 별도 도메인은 필수가 아니다. 먼저 서비스 제공자의 기본 HTTPS 주소로 진행하고, 실제 운영 주소를 정한 뒤 기록이 쌓이도록 권장한다.

배포 자료는 [배포 폴더 안내](../deploy/README.md)를 따른다. 정적 호스팅에는 `deploy/demo-site`의 내용만 올린다. 계정·접근 제한은 호스팅 서비스에서 설정한다. 전체 교재 분석표·교사용 문서·JSON 내보내기 파일을 공개 웹 폴더에 함께 올리지 않는다. 현재 데모는 정답과 교사 참고 내용이 HTML에 포함되므로 교직원 검토 범위로 제공한다.

현재 주소를 바꾸면 브라우저 기록이 자동 이전되지 않는다. 새 주소에서는 가상 기록으로 다시 테스트한다. 내보낸 JSON에는 내부 메모도 들어 있으므로 학부모 자료로 전달하지 않고, 교사 화면의 확정 부모 자료 출력을 사용한다.

## 3. 실제 기기에서 반드시 확인할 항목

실제 브라우저 실행이 이 환경에서 차단되어 아래는 사람이 테스트 주소에 접속해 확인해야 한다. 코드·모의 DOM 통과를 이 검사 완료로 처리하지 않는다.

| 항목 | 확인할 동작 | 합격 기준 |
| --- | --- | --- |
| PC·태블릿·휴대폰 | 실제 기기,320/375/768px 및 큰 화면 | 가로 잘림·겹침 없이 모든 버튼·입력 사용 가능 |
| 브라우저 | 학원 PC Chrome/Edge와 실제 iPhone/iPad Safari 등 사용 기기 | 핵심 흐름과 저장 복원이 동일하게 동작 |
| 진단 | 드래그와 단어·뜻 선택, 모르겠음, 전체 제출 | 중복 배치 없음, 자동 정답을 학생 독립 정답으로 세지 않음 |
| 객관 문제 | 네 보기·힌트·첫 제출·재시도·뒤로가기 | 정답 포함4보기, 선택 보존, 최초 답·분류 기록 유지 |
| 전수 작문 | 10개 개별/일괄 제출, 수정본, 뒤로가기·새로고침 | 해당 단어의 모든 작성·제출·수정 기록 유지 |
| 교사 평가 | 세 판정 버튼, 버전 왕복, 자동 앎→수동 애매함 | 버전별 초안 보존, 확정 후 다음 배정에 반영 |
| 기간 복습 | 주간·월간·분기 전수,5개 중간 저장·이어하기 | 학습 대상 전체 확인, 중복 집계·응답 소실 없음 |
| 저장·재접속 | 같은 브라우저 새로고침·닫기/재접속, 저장 제한 | 복원 정상, 실패 시 실제 저장 성공으로 안내하지 않음 |
| 입력 접근성 | Tab/Enter·포커스·보기 선택·작문 이름 | 마우스 없이 조작 가능, 선택/입력 대상 식별 가능 |
| 부모 출력 | 앱 인쇄·Ctrl+P·PDF 저장·흑백·긴 메시지 | 최신 확정 내용, 차트/표 누락·잘림 없음, 내부 메모 제외 |
| 배포 주소 접근 | 교직원 허용·비허용 접속 | 호스팅 접근 제한이 실제로 적용됨 |

문제 보고는 사용 기기/브라우저, 화면·동작, 예상/실제 결과, 재현 순서, 화면 또는 출력 자료로 남긴다. 가상 기록을 사용한다.

## 4. 실제 학생 파일럿 전에 구현할 기능

기존 PRD와 상세 명세의 범위 안에서 다음을 하나의 완결된 흐름으로 개발한다.

1. 학생·교사 로그인과 학원·반·학생별 접근 권한. 학생은 자신의 과제·답안만 보고 교사는 담당 학생만 검토한다.
2. 서버에 진단·첫 답·힌트·재시도·10단어 작문·수정본·교사 확정 평가를 저장하고 다른 기기에서 복원한다. 중복 제출·저장 실패·백업 복원도 검수한다.
3. 학생에게 배정한 승인 문항을 제공하고 정답은 최초 제출/공개 규칙에 따라 처리한다. 교사용 정답·미확정 의견을 학생 화면 데이터에 함께 보내지 않는다.
4. 한국 시간 기준 일간·주간·월간 리포트와 주간·월간·분기 전체 복습 대상을 실제 학습 기록에서 집계한다. 진행 중 계획은 고정하고 교사의 최신 확정 분류는 다음 계획에 반영한다.
5. 학생별 교사 평가·부모 메시지·차트·PDF를 제공한다. 확정 버전과 출력 재시도, 내부 메모 제외를 확인한다.

전수 작문과3버튼 판정·수동 애매함·60/30/10, 교재 순서와 기록 불변 규칙을 유지한다. 기능 선택지를 다시 정하기보다 현재 상세 명세를 구현 기준으로 사용한다. 프레임워크·DB 제품 선택은 개발 담당이 권한·저장·운영 요구에 맞게 결정한다.

국어 담당자는 첫10개 뜻·160문항·20작문 질문과 원문4개 교정 이슈를 검수한다. 사전 대조·사용 범위·단일 정답·학년 적합성을 승인하고 교재 디지털 이용 범위를 확인한다. 현재 초안 상태를 자동 승인으로 바꾸지 않으며 미승인 단어를 건너뛰어 다른 단어로 교체하지 않는다.

실서비스 검수63사례에 실제 실행 증거를 붙인다. 학습 시작·저장·권한·채점·보고서의 필수 검수를 통과하고 해당 학원 기기와 인쇄 문제를 해결한 뒤 실제 학생을 시작한다.

## 5. 권장 파일럿 규모와 운영

기존4주 계획을 유지하되 먼저 학원1곳·반1개·학생5–10명·교사1–2명으로 작게 시작하는 안을 권장한다. 기존30명안으로 확대하기 전에 작문 확인 시간을 확인한다.

- 1주: 계정·기기·교사 연습, 승인 콘텐츠와 사전 평가 확인.
- 2~3주: 정규6회 객관60개, 첫10개 전수 초고10개, 교사 피드백·수정·주간 복습.
- 4주: 사후 평가·보고서·업무량·저장/지원 문제 확인. 지연 평가는 각 단어의 마지막 의미 있는 학습·수정·복습에서7일 이후로 따로 잡는다.

학생10명의 신규 작문은100건이다. 건당3분 가정이면 초고 검토300분이 필요하고 수정본·부모 메시지·지원 시간은 추가다. 이는 실측값이 아니며 실제 검토 시간과 다음 수업 전 피드백 완료율을 기록한다. 분기 기능은 날짜 경계 시험 자료로 검수하고 실제 분기 학습 효과는3개월 운영 후 평가한다.

처음 정할 사항은 테스트 호스팅을 관리할 계정/담당자, 참여 학원·교사·기기, 교육 검수 담당자와 날짜다. 기능·데이터·디자인 기준은 기존 문서를 유지한다. 학생별 기록을 수집할 파일럿은 위 서버·권한 개발과 교육 승인을 마친 뒤 진행한다.
